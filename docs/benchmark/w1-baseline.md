# W1 기준선 — NDJSON 원본

측정일: 2026-08-08
환경: macOS (darwin 23.4.0), Java 17 (Homebrew OpenJDK), Gradle 8.10.2

## 데이터셋

```
./gradlew :bench:generate --args="--count=10_000_000 --out=data/raw-10m.ndjson"
```

| 항목 | 값 |
|---|---|
| 건수 | 10,000,000 |
| 테넌트 / 디바이스 | 3 / 테넌트당 200 (총 600) |
| 키 | temperature, humidity, power_wh, running, error_code (각 200만 건) |
| 전송 주기 | 10초 |
| 시작 시각 | 2026-01-01T00:00:00Z (고정) |
| 커버 기간 | 약 9시간 |

## 결과

| 지표 | 값 |
|---|---|
| **NDJSON 크기** | **1,966,190,528 bytes (1,875 MiB)** |
| 건당 크기 | 196.6 bytes |
| 생성 시간 | 4.5s |
| 생성 처리량 | 2,237,544 pt/s |

**이 1,875 MiB 가 W3 Parquet 압축률의 분모다.**

## 값 분포 검증

압축률 측정이 의미를 가지려면 합성 데이터가 실제 센서의 압축 특성을 가져야 한다.
`SensorsTest` 가 아래를 회귀 테스트로 고정하고 있다.

| 키 | 압축 전제 | 실측 |
|---|---|---|
| temperature | 델타 인코딩 (완만한 변화) | 10초 간격 최대 변화 < 1.0℃, 고유값 287 (2.3년 표본) |
| humidity | 델타 인코딩 | 범위 52.4~87.1, 고유값 348 |
| power_wh | 비트팩킹 (정수) | 업무시간 패턴 + 0.2% 스파이크 |
| running | RLE | 4시간 런, 28시간에 전환 10회 미만 |
| error_code | 딕셔너리 | "OK" 98%, 카디널리티 5 |

온도-습도 상관계수 **r = −0.820** — 강하지만 완전하지 않다. 실제 센서와 유사.

### 수정 이력: 습도 하드 클램프 제거

최초 구현은 `Math.min(95, Math.max(20, h))` 로 잘랐다. 그 결과:

- 표본의 **3.5%가 정확히 95.0** 에 쌓임
- 95.0 이 단일 최빈값 (6,963회 vs 차순위 806회)

경계값에 표본이 몰리면 딕셔너리/RLE 가 그 값을 공짜로 먹어서 **압축률이 실제보다 좋게 나온다.**
`tanh` 기반 soft clamp 로 교체 후 최빈값 비중 3.5% → 0.57%.
회귀 방지 테스트: `SensorsTest#continuousSensorsHaveNoSpike`.

## W3 진입 전에 정할 것

**현재 기본 설정은 1천만 건이 9시간밖에 커버하지 못한다.** W4 쿼리 3종 중
Q2(1년 일평균), Q3(1개월 평균)를 재려면 1년을 커버하는 데이터셋이 따로 필요하다.

10초 주기 × 600 디바이스로 1년을 채우면 94억 건 — 로컬에서 불가능하다.
아래 중 하나를 골라야 한다.

| 안 | 구성 | 1년 건수 | 비고 |
|---|---|---|---|
| A | 디바이스 50, 주기 60초 | 1.31억 | 유력. NDJSON 약 26GB, Parquet 은 훨씬 작을 것 |
| B | 디바이스 600, 주기 300초 | 3.15억 | 디바이스 카디널리티 유지. 용량 부담 |
| C | 디바이스 600, 주기 10초, 30일만 | 15.5억 | 장기 쿼리 측정 불가 — 탈락 |

→ W3 착수 시 A 안 기준으로 재측정하고 이 문서에 기준선을 추가한다.
   **디바이스 수는 파티셔닝 스킴 C(디렉터리 폭발)의 핵심 변수이므로, 줄일 때 그 영향을 함께 기록할 것.**
